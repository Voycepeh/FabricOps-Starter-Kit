# Setup Fabric Workspace

Prepare Fabric workspaces, lakehouses, warehouse, a Fabric Environment, the FabricOps wheel, and copied notebook templates before running the guided demo notebook flow.

## Purpose

This setup page gets your Microsoft Fabric runtime ready so every copied demo notebook can import `fabricops_kit` and write to the intended configured targets. Complete this page before [Configure Environment](configure-environment.md).

## Required Fabric items

Create one Governance workspace and one Engineering workspace. For a lightweight demo, you may use a single workspace if that is easier, but keep the item roles clear so the `00_env_config` routes are easy to understand.

| Workspace | Required item | Purpose |
| --------- | ------------- | ------- |
| Governance workspace | `metadata_lakehouse` | Stores shared metadata, notebook registration, agreements, profiles, reviewed guardrail expectations, classifications, lineage evidence, and run evidence. |
| Engineering workspace | `source_lakehouse` | Hosts deterministic `demo_` source tables generated by `example_pipeline_demo`. |
| Engineering workspace | `unified_lakehouse` | Hosts governed unified outputs written by `02_pipeline`. |
| Engineering workspace | `product_warehouse` | Hosts warehouse outputs or demos that need a warehouse target. |

## Install the FabricOps wheel in a Fabric Environment

**Open:** [Install](../install.md), then your Microsoft Fabric workspace and Fabric Environment.

1. Build or download the FabricOps wheel. The standard local build flow is documented in [Install](../install.md) and [Setup: Create Wheel](../setup/create-wheel.md).
2. Open the target Fabric workspace.
3. Create a new Fabric Environment, or open the Environment that should run your FabricOps notebooks.
4. Go to **Libraries** / **Custom libraries**.
5. Upload the generated wheel from your local `dist/` folder, for example `dist/fabricops_kit-0.1.0-py3-none-any.whl`. The exact version number may differ.
6. Save or publish the Environment so Fabric applies the library change.
7. Restart notebook sessions after changing the Environment if Fabric prompts you or if sessions were already running.

## Copy notebook templates into Fabric

Copy editable notebook templates from the GitHub `templates` folder into your Fabric workspace. Keep the names recognizable for the first guided demo run:

| Notebook template | Role in the guided demo |
| ----------------- | ----------------------- |
| `00_env_config` | Defines shared environment, workspace, lakehouse, warehouse, metadata target, and audit settings. |
| `01_agreement` | Captures steward, agreement, and agreement evidence metadata. |
| `02_pipeline` | Runs governed source-to-target processing, profiles data, evaluates guardrails, writes outputs, and records run evidence. |
| `03_governance` | Reviews observed metadata, enrichment intent, and guardrail intent. |
| `example_pipeline_demo` | Generates deterministic demo source scenarios and demo-scoped DQ rules. |
| `99_explore` | Supports optional read-only discovery or troubleshooting. |

## Attach the Environment to copied notebooks

1. Open each copied notebook template in Fabric.
2. Select the Fabric Environment that contains the uploaded FabricOps wheel.
3. Save the notebook after selecting the Environment.
4. Restart the notebook session if the session was already running.
5. Verify the import in at least one copied notebook:

```python
import fabricops_kit as fsk

print(f"FabricOps Starter Kit version: {fsk.__version__}")
print(f"Available helper count: {len(fsk.__all__)}")
```
